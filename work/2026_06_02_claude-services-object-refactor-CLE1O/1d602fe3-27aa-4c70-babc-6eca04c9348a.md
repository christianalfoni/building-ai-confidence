## What I'm proposing

**New services** (interfaces in `services/index.ts`, impls split client/server):

| Service | Owns | Methods |
|---|---|---|
| `SessionService` | `user`, `isPreview` | `signOut()` → POST `/auth/logout` |
| `NavigationService` | `route` | `navigate(path)` → `window.location.href = path` |
| `DatabaseService` *(existing)* | posts CRUD | unchanged |

**`AppState` constructor** changes from positional args to a single object:

```ts
// before
new AppState(user, isPreview, dbPosts, db, route)
// after
new AppState({ database, session, navigation }, { dbPosts })
```

`user`/`isPreview` come from `session`, `view`/`selectedPostId` from `navigation.route`, and the `window.location.href = '/'` redirects in `signOut`/`deletePost` route through `navigation.navigate('/')`.

## Key design decisions
- **`database` stays nullable** — the server passes `null` (SSR is read-only) and the existing `if (!this.database)` guards are preserved, so zero behavioural risk.
- **`isPreview` lives on `SessionService`** — it drives the sign-in UI, so it's grouped with the user/auth concern.
- **Server services throw on `signOut()`/`navigate()`** — mirroring how the client `DatabaseService` throws on server-only methods; never called during SSR.
- A nice side-effect: the `deletePost` test no longer needs to monkey-patch `window.location` — it asserts on a fake navigation service instead.
